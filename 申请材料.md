### 2. 这个仓库为什么符合条件（关键字段）

这是最重要的一个字段。不要只写 star 数——新仓库没有 star。要写清楚
**这个项目解决什么问题、为什么值得被工具链依赖**。

英文原文（可直接粘贴）：

> chipnum extracts, normalises and classifies semiconductor part numbers
> (MPNs) from free text — prose, tables, CSV cells and BOM files — and
> resolves each one to a vendor and component category.
>
> Part numbers are written by humans, in prose, in every conceivable
> spelling: `stm32f103c8t6`, `STM32-F103`, `STM32 F103`, `ＳＴＭ３２Ｆ１０３`.
> A BOM column, a WeChat article about chip shortages, and a distributor's
> quote all spell the same die differently. Existing tooling generally assumes
> you already have a clean, delimited list, leaving the hard part — pulling
> MPNs out of running text and knowing which vendor a prefix belongs to — to
> the user.
>
> The vendor table is data, not code: adding or correcting a vendor is a TOML
> edit, never a Python change. That matters because the table is the part
> maintained by people who are not the original author, and by automated
> mining over real corpora.
>
> The library is built around a single design rule: reporting "unknown" is
> correct, confidently naming the wrong vendor is not. A wrong vendor
> propagates into sourcing decisions, so every match carries a confidence
> level, a two-character prefix can never outrank a longer one, and the
> package ships an audit tool that checks the table for prefix collisions and
> shadowing against real corpora.
>
> Why it matters: MPN resolution is a prerequisite step in every electronic
> supply-chain workflow — BOM normalisation, part-number deduplication across
> distributors, counterfeit screening, market and price tracking, and
> component-obsolescence monitoring. Those workflows are currently done by
> hand, or by scripts that break on the first unusual spelling. chipnum is
> infrastructure for that step, and it is designed to be corrected and
> extended by the community rather than locked behind an API.

### 3. 计划怎么用 Codex（关键字段）

英文原文（可直接粘贴）：

> chipnum is a small, pure-Python package with no runtime dependencies, and
> the work is exactly the kind Codex is good at.
>
> **PR review.** The vendor prefix tables are where precision matters most
> and where regressions are silent — a two-character prefix that claims
> `IPD50N06S2L` (an Infineon OptiMOS) for a different vendor produces a
> confidently wrong answer that no unit test would catch unless one is
> written. Reviewing a PR that adds prefixes against the audit rules
> (minimum prefix length, specificity, corpus coverage) is a good use of
> Codex, and it is the kind of review that benefits from a model which can
> hold the whole table in context.
>
> **Issue triage and reproduction.** The most common issue will be "chipnum
> named the wrong vendor for this part number". The issue template already
> captures the part number, the expected vendor, the input text and the
> command. Codex can turn that into a minimal regression test and, where the
> fix is a missing prefix, a patch to the right TOML table.
>
> **Release workflow.** Version bumps, changelog entries generated from
> commits, and PyPI publishing are mechanical and well-suited to automation,
> leaving human review for the parts that need judgement.
>
> **Test generation.** The corpus regression suite is built from a
> hand-checked subset of a 7,441-part-number corpus. Codex can help expand
> that subset, especially for the long tail of passive components, and can
> generate property-based tests for the normalisation rules (full-width
> folding, separator canonicalisation, edge trimming) where the interesting
> cases are combinatorial.
>
> **Documentation.** The vendor table is the documentation, and it drifts.
> Codex can keep `docs/adding-vendors.md` and the table's own comments
> consistent with what the table actually contains, and can help produce
> per-vendor notes from real part numbers.

## 关于通过率说实话

新仓库 0 star 申请，通过率不高。官方三个审核信号是：

1. **仓库使用量** — 新仓库是 0
2. **生态重要性** — 这个可以论证，MPN 解析是供应链流程的前置步骤
3. **活跃维护证据** — PR review / issue triage / release 管理

第 3 条最关键，所以**仓库必须看起来是活的**：有 issue、有 PR、有 release、
有讨论。所以下一步不是干等审核，而是把上面那五个 checkbox 做掉。

滚动审核，之前拿到过资助的人可以重新申请。所以**先申请一次不吃亏**，
等攒出真实信号再补交一次。
